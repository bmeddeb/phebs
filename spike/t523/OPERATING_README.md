# T52.3 prospective operating matrix

This is source preparation, with no candidate, signing, native, browser or
operating execution yet. The existing T52.3 validation receipts and all T52.1 /
T52.2 inputs, labels, witnesses and first results remain unchanged. Production
signing is pending the existing unavailable Linux key.

`operating-plan.json` fixes the query population and limits before output.
`operating-inputs.json` binds the complete two evaluator Git trees, independently
from their original upstream provenance: Apache has40files/1,175,947bytes and
thriftrw8files/115,660bytes, totaling48files/1,291,607bytes. Their committed root
SCIP indexes and generated bytes are reused; this matrix invokes no indexer,
generator, new source recognizer or direct source-quality scorer.

The three ordinary starts select Apache only, both packs, then thriftrw after
Apache withdrawal. They use the same two repositories throughout, without a
source transition. Both input origins must retain the exact symbolic HEAD and
commit recorded in the input binding. Distinct branch names in independent
repositories are allowed. The own census verifier admits at most64regular files
per repository, requires every exact frozen path/blob/size and the exact48-file
aggregate, and retains the16MiB aggregate ceiling. It does not change T50.3's
separate32-file helper bound.

Only neutral `find_field_references` is exercised. Apache facts retain
`derived/none`; thriftrw facts retain `exact/module_digest`, including its
existing generated-only field0 witness. The fixed native query population is
the9Apache public positive identities,2thriftrw positive identities and one
thriftrw field0 identity. Returned consumer facts must match all33/4original
positive spans exactly; every other consumer span in those queries refuses.
These queries do not inventory every possible field identity. The earlier
full-stream direct T52.1/T52.2 negative-site results retain their own scope;
there is no new global negative-field recall or pooled accuracy claim here.
Each phase receipt carries this native query scope explicitly. Its verified
native opportunities/spans and extra facts within the fixed queries are
separate from `prior_frozen_negative_sites`, which names prior label context
without scoring those sites again.

Field0 is a numeric-zero transport-admission mechanics query only, with no
generated-reference recall denominator. A zero-fact response makes no live
reference or source/runtime absence claim. The receipt records the number of
returned generated references and makes a live-reference claim only for
returned facts whose exact source/span was validated; no new field0 label,
fixture or consumer opportunity is added.

Every returned generated-file span is validated separately, without a generated
recall denominator. The pinned SCIP inputs mark these references as raw`read`;
that is not semantic read/write truth. Existing `codeRole` recognizes`.gen/go/`
as generated but Apache`thrift-gen/`source as production when SCIP has no
Generated bit. The checker preserves that existing metadata and explicitly
separates generated-source paths from consumer quality. It does not claim that
the Apache role attribute independently identifies generated code.

Every proof checks both visible current roots, not just the queried field's
repository, with the exact selected-set version and source/run/plan/root tuple.
An unselected generator may return0facts only with the same coherent global
metadata; this means pack unavailable, never source/runtime absence. Five
selected native metadata reads per repository and phase bind candidate/source
generations without a corpus scan. All current-source queries, MCP projections,
immutable proof IDs and surviving source facts are checked against that epoch.

The first successful request per object is called cold only after explicit
publication probes; process/shared caches may already be warm. Five warm reads
per object follow. Only the both phase runs finite1/4/8-client whole-proof
batches, with no pagination. Exact source transport opens each unique selected
consumer blob once over HTTP and once over MCP per phase, then checks all byte
slices client-side. There is no new source-range service or instrumented blob
read-count claim.

The single180-second clock starts before disposable signing and includes all
three starts, measured actions and joined teardown. Existing30-second startup,
90-second publication,2/1-second cold/warm and1MiB response bounds remain. The
sampler uses observed process-tree RSS maxima (2GiB), not a proven transient
peak or hard limit. Available physical headroom must stay at least4GiB without
swap/compressor credit; derived allocation is capped512MiB. Missing measurement,
forced cleanup, unjoined ownership or the first mismatch stops the attempt.

T50.3 code; accepted T51.3 canonicalization and failure cleanup are imported.
They must be integrated repository-relatively and hashed in the final execution
binding before import. No other-worktree fallback is allowed. This worktree
currently lacks those helper files, so source preparation alone is not runnable.
The reuse is code reuse, not a transfer of T50.3/T51.3 operating outcomes.
