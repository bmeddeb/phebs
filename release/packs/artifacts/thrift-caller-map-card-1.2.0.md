# Claim card: phebs.thrift.caller.go 1.2.0 (Thrift Caller Map)

Owner: Ben Meddeb. Distribution: default-on in the release package
(PHEBS-42, 2026-11-25; claim 1.1.0 adds thriftrw/YARPC clients, PHEBS-46,
2026-11-26). Claim 1.2.0
(PHEBS-47, 2026-11-27) reads declarations from thriftrw's embedded IDL too. This card
supersedes `thrift-caller-map-card-1.1.0.md`.

**Qualification.** Bounded integration tests and the `ci-static`, `ci-go` and
`ci-race` gates on the exact head, under Ben's 2026-11-08 acceptance rule. No
independent blind-label round, precision, recall, attribution accuracy,
completeness, capacity or scale claim is made.

**Scope.** Go callers of Thrift clients in the same repository as the
`.thrift` declaration they were generated from, for two generators.

*Apache Thrift compiler clients.* A resolved row needs all of the following:

- a call to one generated client method (the generated file carries the
  Thrift compiler header and the method's `Call` wire literal);
- exactly one direct `generated_path` → `declaration_path` mapping for that
  generated file in the repository-root `generated-from-snapshot.json`
  (version `t20-generated-from-v1`), committed at the same revision. phebs
  never infers this relation from paths, layout or the generator header;
- that declaration's `thrift-contract` operation for the same service and
  method, which supplies the declaration lineage and the operation's
  spelling. The generated Go package is not used as the Thrift scope (the
  compiler lowercases the IDL name when no `namespace go` is set), so a caller
  is served under the operation Contract Atlas shows. A generated method that
  the mapped declaration does not declare is an explicit abstention.

Without that committed mapping a call is an explicit abstention, never a
resolved caller.

*thriftrw + thriftrw-plugin-yarpc clients* (PHEBS-46, Ben's option B). A
resolved row needs all of the following, and no `generated-from-snapshot.json`
entry for the client file (an explicit mapping governs):

- a call through a generated client's `Interface`, held from its `New(...)`
  or as an `Interface` value; the client file's first line is exactly
  `// Code generated by thriftrw-plugin-yarpc`;
- the one thriftrw package the client's `<Service>_<Method>_Helper.Args`
  calls go through, located through the repository's own `go.mod` modules,
  holding exactly one thriftrw file (`// Code generated by thriftrw vX.Y.Z`)
  whose embedded `ThriftModule.Package` is that import path;
- exactly one `.thrift` file with declared operations whose path equals the
  module's `FilePath` or ends in `/FilePath`, and whose content SHA-1 equals
  the module's `SHA1`; or, when no committed `.thrift` sits at `FilePath`,
  the module file itself, whose digest-valid embedded IDL `thrift-contract`
  declares (claim 1.2.0, PHEBS-47). phebs verifies this provenance; it never
  infers the relation from directory names;
- that declaration's `thrift-contract` operation for the `thrift.Config`
  service literal and the method's `MethodName()` spelling (the Go method
  `Echo` is the Thrift method `echo`).

A hash mismatch or several matching files is an explicit abstention. A client
whose thriftrw package cannot be found is not described, so its calls are not
reported. Methods inherited through `extends` from another service are not
resolved.

The surfaces are those of the protobuf Caller Map, for `protocol=thrift`:

- the existing authenticated exact Caller Map, progress and citation routes;
- the MCP tools `list_operation_callers` and
  `read_operation_caller_citation`;
- the Caller Map view reached from a Thrift operation in Contract Atlas;
- the capability `contract-caller-map`.

**Recipe.** `thrift-contract@1.2.0` with `thrift-caller@1.6.0-released.1`.
The caller algorithm is `thrift-caller` 1.6.0 unchanged, the reader shipped
dark since T20.8. It resolves through the shared T30.6g resolver catalog at
resolver pack version 1.5.0, whose materialization policy names the Thrift
operation binding `mapped-declaration-service-method-v1` (PHEBS-42) and the
thriftrw provenance rule `thriftrw-yarpc-module-package-sha1-embedded-v2` (PHEBS-46, PHEBS-47). The
distinct admission version separates candidate and caller generation
identities, so experimental Thrift caller publications are refused by the
existing read fences and replaced through startup reconciliation.

**Non-claims.**

- Kitex, fbthrift and other generators are not resolved, nor are
  thriftrw/YARPC clients whose committed `.thrift` has a different SHA-1.
  Their calls are absent or explicit abstentions, never resolved callers.
- No name-matching consumer evidence (`thrift-consumer`, T58 NO-GO).
- Caller comparison and operation Impact for Thrift are their own claims
  (`phebs.thrift.caller.comparison`, `phebs.thrift.impact.operation`).
- No runtime execution, deployment, complete inventory or safe-retirement
  claim. Empty results never prove caller absence.

**Limits.** The existing candidate, publication, reader, request and citation
bounds apply unchanged. No ceiling is widened, and no latency, memory,
service-count or repository-size envelope is claimed.

**Evidence.** `thrift-caller-map-validation-1.2.0.json` records the commands
and results. The signed release binds the running binary, the recipe registry
and these artifacts.

expiry of the Thrift declaration claim (`phebs.thrift.contract`) whose
