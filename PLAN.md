| 2026-07-22 | T10.4 bounded multi-revision indexing | **HEAD stays implicit and authoritative; extra revisions are explicit search-only scopes.** `revisions` maps a canonical repository name to at most seven case-sensitive query selectors and full `refs/heads/*` / `refs/tags/*` refs, keeping the PLAN ceiling at eight revisions including HEAD; wildcard, short/ambiguous, commit-id, duplicate, and unsafe refs fail config admission. ### 1.1 Why upstream-only dissolves shard compatibility

The port owns both sides of the shard boundary: our binary reads shards, and our
container builds the writer from the *same module version*
(`go build github.com/sourcegraph/zoekt/cmd/zoekt-git-index`). Compatibility with
fork-written shards stops mattering — reindex at cutover.

### 1.2 Fleet profile (P6)

N homogeneous replicas of the same binary. Each owns a rendezvous-hashed repo
subset: indexes it, serves it from local NVMe shards. gRPC scatter-gather across
replicas for queries; SurrealDB cut over from the supervised local child to an
external server deployment (export/import);
owner-scoped job claims; admission control with **separate interactive and agent
traffic budgets**. Standalone remains the dev/small default; fleet lands last so
single-node correctness is proved first.

| 2026-07-12 | Evidence & proof-bundle model (annex) | **Content identity ≠ occurrence identity.** Evidence atoms are content-keyed — `evidence_atom_id = H(schema_version, blob_digest, byte_span, rule_id, extractor_version, adapter_config_digest, fact_fingerprint)` (`fact_fingerprint` disambiguates multiple assertions from one span) — so identical vendored blobs dedupe across commits and repositories; repository placement lives in separate `snapshot_evidence` associations `(evidence_atom_id, repository_id, snapshot_id, commit, path, visibility_scope)`, preserving per-repo authorization and provenance through dedup; `last_verified` derives from snapshot associations; association compaction never deletes shared atoms. Layers: semantic assertions ← supporting **and contradicting** atoms; identity assertions (logical service, deployable, build target, image, workload, and runtime `service.name` are related entities, **never aliases**; unresolved identity is successful abstention); coverage manifests; extraction runs published atomically via staging (a failed run never publishes a partial replacement set); resolved edges materialized separately. Confidence is deterministic tiers (`exact/derived/heuristic/unresolved`); numeric confidence only after empirical calibration on blind holdouts. **Proof bundles are self-contained, not self-authorizing**: each embeds its assertions, coverage certificate, extractor versions, and a `visibility_context` (principal, authorization provider, permission snapshot, visible-repository-set digest); bundle scope is the caller's visible universe — coverage never names *or counts* invisible repositories; permission filtering precedes assertion/count/coverage computation; admin and member queries yield different immutable bundle IDs; revoking repository access revokes access to old bundles; possession of a bundle ID is not authorization (consumers re-authorize through phebs on read). Contract identity: operations = fully-qualified proto service+method; fields = `(contract_lineage_id, message_full_name, field_number)` — the field number is the wire identity, the name a versioned attribute; forked or unrelated descriptor sets reusing names/numbers stay separate until identity resolution proves shared lineage. **Pure-reader invariant**: extractors never execute corpus-provided code, generators, plugins, build scripts, or binaries; never dynamically load corpus artifacts; never write into the corpus; no network access while parsing it. Commodity proto compatibility via a version-pinned `buf` child binary built from go.mod (the zoekt-git-index house pattern, not Buf's unstable Go internals): phebs-produced descriptor inputs or a sanitized temp tree, network disabled, CPU/memory/time limits, never `buf generate`/protoc plugins/repository scripts; Buf version, arguments, and result recorded in the extraction run. **Retention is proof-aware**: content-addressed atom dedup, snapshot-association compaction, proof-bundle and release/migration-checkpoint pinning; no time-only deletion of evidence referenced by a retained bundle; compaction only after no retained assertion or bundle references the association (full compaction design deferred past T11.1; the schema must not preclude it). **Bounded negative proof**: phebs never asserts "safe to decommission" / "no consumers exist" / "migration complete" — only "no blockers found within the stated evidence scope," always accompanied by the coverage certificate. |
